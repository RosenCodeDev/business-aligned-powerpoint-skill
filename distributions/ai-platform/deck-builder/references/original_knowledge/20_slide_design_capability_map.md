# Oliver Wyman Slide Design — Capability Map

Compact, **always-load** reference for design selection: which of the OW slide
designs the runtime can produce and the intent to build each with. Cautions are
inline in the table. For full design rationale (when/why to use each design),
see the on-demand reference `21_slide_design_selection_guide.md`.

## Runtime capability mapping (authoritative — read before selecting a design)

The deck is generated by the template-native runtime, which builds slides from a
fixed set of **intents** — not by hand-placing shapes. The 27 designs below are
the visual vocabulary; this table says which the runtime can actually produce and
how. **Only generate designs marked Supported or Approximate.** For "Needs image"
designs, proceed only if the user supplied an image file. For "Not yet available"
designs, use the listed alternative — never hand-build a slide outside the runtime
(see ABSOLUTE RULES in the instructions).

| # | Design | Status | Build with (intent) / fallback |
|---|---|---|---|

line, area, pie, doughnut, scatter. Matrices and timelines are **not** chart types.

Matrix, timeline, growing-steps, and contents are now Supported (any size —
`rows`×`cols` for matrices; any milestone, step, or section count).


## Graphic + text (split layout)

Any graphic can be paired with supporting text side-by-side instead of running
full-width, via **`show_graphic_with_text`**: `panel.graphic.kind` is one of
growing_steps / pyramid / cycle / org_chart / process / matrix / timeline, and
`panel.text` carries a heading, optional subheading, and bullets or paragraphs.
Set `panel.side` to `graphic_left` (graphic supported by text on the right) or
`graphic_right` (graphic supports the text on the left). Use this when a visual
needs a paragraph of explanation beside it; use the plain full-width graphic
intent when the visual speaks for itself.
| Waterfall / bridge chart (vertical or horizontal) | `show_waterfall` | cumulative build/bridge; totals from zero, +/- deltas |
| Treemap (part-to-whole, many categories) | `show_treemap` | rectangles sized by value, squarified, labelled |
| Heterogeneous slide (e.g. chart + commentary columns) no preset covers | `compose` | open grid of blocks; routed to only when preset fit < threshold |

## Composite components (Supported — canvas intents)
Use these to merge text with icons/shapes the OW way (from the component library):

| Design need | Intent | Content |
|---|---|---|
| One-to-four **big numbers** with a heading + line of text | `stat_callout` | `{title, stats:[{value, heading, text}]}` |
| A short list where each item is **icon + heading + text** | `icon_rows` | `{title, rows:[{icon, heading, text}]}` |
| A **pros vs cons** / do vs don't check-cross split | `compare` | `{title, compare:{pros:[...], cons:[...], pros_heading?, cons_heading?}}` |

All are Supported on the `Title Only` canvas, brand-styled (navy/cream/amber, Marsh Serif numbers, fine-line icons). Prefer them over `compose` when one fits.

### Accents & variadic (added)
- `sticker` — amber circular highlight + note: `{title, sticker:{text, note?}}`.
- **All components are variadic** — any number of stats/rows/banners/labels; stat cards auto-wrap to a grid. Use as many as the content needs.

### Infographics & compose blocks (added)
- `infographic` — native-freeform: `type:funnel` `{stages:[{label,value}]}`, `type:gauge` `{value,label}`, `type:venn` `{sets:[{label}]}`. All editable shapes, no SVG.
- **Components & infographics are also `compose` block kinds** — put any number of `stat_callout`, `icon_rows`, `compare`, `sticker`, or `infographic` blocks into `compose` regions to mix them with charts/text in any layout.
- `infographic type:heatmap` — grid of native cells (e.g. 10×10) with axis labels and a stepped legend: `{values:[[..]], x_labels?, y_labels?, steps?, legend_labels?, description?}`. Cell outline = slide background, 1pt; fill = value on a cream→navy scale.

## Grid & text styles (enforced)
- Two-pane slides (`graphic_with_text`) are **grid layouts**: `equal` (default) is a 2-column grid; `split:graphic_2_3` / `split:text_2_3` are a 3-column grid with one pane spanning two columns. Their proportions are computed from the grid column width, so they are **identical to what `compose.grid` produces** — there is no separate ratio rule. For arbitrary N×M layouts with spanning, use `compose.grid` (see `50_design_system.md`).
- Component/card text uses the design system: **Heading 12pt bold, body 12pt, default navy** (no custom greys). Icons on cards: 0.2" inset from top/left, 0.5" tall, text at a 0.9" top margin.
- Removed components (do not offer): brackets/braces, filled-arrow banners, label_stack.
